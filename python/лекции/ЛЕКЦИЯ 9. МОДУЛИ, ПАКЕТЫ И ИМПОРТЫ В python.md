
Цель занятия: научиться разделять Python-код на отдельные файлы и модули, импортировать функции и классы, организовывать структуру проекта и понимать, как эти знания применяются в backend-разработке.

## 9.1. Что такое модуль в Python

До этого мы писали программы преимущественно в одном файле. Для небольших задач это удобно, но по мере роста проекта такой подход становится проблематичным.

Представим, что мы разрабатываем интернет-магазин. В программе есть:

- регистрация пользователей;
    
- авторизация;
    
- работа с товарами;
    
- обработка заказов;
    
- подключение к базе данных;
    
- отправка уведомлений.
    

Если поместить всю логику в один файл, он быстро станет большим и сложным для сопровождения.

Для решения этой проблемы Python позволяет разделять программу на отдельные файлы.

Модуль — это файл Python с расширением `.py`, содержащий код, который можно использовать в других частях программы.

Например, создадим два файла:

```
project/
├── main.py
└── calculator.py
```

В файле `calculator.py` разместим функции для математических операций:

```python
def add(a, b):
    return a + b
def subtract(a, b):
    return a - b
def multiply(a, b):
    return a * b
```

Теперь в файле `main.py` можно использовать эти функции.

```python
import calculator
result = calculator.add(10, 5)
print(result)
```

Результат выполнения:

```
15
```

Что произошло?

1. Python встретил инструкцию `import calculator`.
    
2. Нашёл модуль `calculator`.
    
3. Загрузил его и выполнил код верхнего уровня, если модуль ещё не был загружен.
    
4. Предоставил доступ к функциям через имя модуля.
    
5. При вызове `calculator.add(10, 5)` выполнилась функция из другого файла.
    

Обратите внимание: мы не копировали функцию `add()` в `main.py`, а использовали её из другого модуля.

### Зачем нужны модули

Модули помогают:

- разделять программу на логические части;
    
- повторно использовать написанный код;
    
- упрощать поиск ошибок;
    
- облегчать тестирование;
    
- работать над проектом нескольким разработчикам;
    
- поддерживать понятную структуру приложения.
    

В backend-разработке это особенно важно: работа с пользователями, заказами и базой данных обычно разделяется на разные модули.

## 9.2. Импорт модулей: `import`

Самый простой способ подключить модуль — использовать инструкцию `import`.

```python
import math
print(math.sqrt(25))
print(math.pi)
```

Результат:

```
5.0
3.141592653589793
```

Здесь `math` — модуль стандартной библиотеки Python, содержащий математические функции и константы.

Когда мы пишем:

```python
import math
```

мы получаем доступ к содержимому модуля через его имя.

Обращение к объектам выполняется через точку:

```python
math.sqrt(25)
math.pimath.factorial(5)
```

Точка позволяет обратиться к определённому объекту внутри модуля.

### Импорт нескольких модулей

Можно импортировать несколько модулей в одном файле:

```python
import mathimport randomimport datetime
```

Каждый из них предоставляет собственные возможности:

- `math` — математические операции;
    
- `random` — генерация случайных значений;
    
- `datetime` — работа с датами и временем.
    

Пример:

```python
import random
import math
number = random.randint(1, 100)
print("Случайное число:", number)
print("Квадратный корень:", math.sqrt(number))
```

Здесь `random.randint(1, 100)` возвращает случайное целое число от 1 до 100 включительно.

### Импорт конкретных объектов: `from ... import`

Иногда нам не нужен весь модуль. Мы хотим использовать только определённую функцию или переменную.

Для этого применяется конструкция `from ... import`.

```python
from math import sqrt, pi
print(sqrt(36))
print(pi)
```

Результат:

```
6.0
3.141592653589793
```

Теперь мы можем обращаться к `sqrt()` и `pi` напрямую, без префикса `math.`.

Сравним два варианта.

Первый вариант:

```python
import mathresult = math.sqrt(49)
```

Второй вариант:

```python
from math import sqrt
result = sqrt(49)
```

Оба варианта корректны.

Первый явно показывает, откуда пришла функция. Второй позволяет обращаться к ней короче.

Для больших проектов часто удобно использовать `import module`, поскольку происхождение объектов видно непосредственно в коде.

### Импорт всего содержимого через `*`

Python позволяет написать:

```python
from math import *
print(sqrt(64))
print(pi)
```

Однако такой способ обычно не рекомендуется.

Почему?

Представим, что мы импортировали десятки функций из разных модулей. В результате может оказаться непонятно, откуда взялась конкретная функция.

Кроме того, имена из разных модулей могут конфликтовать.

Поэтому предпочтительнее использовать:

```python
import math
```

или:

```python
from math import sqrt, pi
```

## 9.3. Псевдонимы через `as`

Иногда имя модуля слишком длинное или нам хочется дать ему более удобное обозначение.

Для этого используется ключевое слово `as`.

```python
import math as m
print(m.sqrt(81))
```

Результат:

```
9.0
```

Теперь модуль `math` доступен под именем `m`.

Псевдонимы также применяются при импорте конкретных объектов:

```python
from math import factorial as fact
print(fact(5))
```

Результат:

```
120
```

Однако не стоит чрезмерно сокращать имена без необходимости. Код должен оставаться понятным другим разработчикам.

В реальных проектах существуют распространённые псевдонимы. Например, в аналитике данных часто встречается `import pandas as pd`, но в backend-приложениях необходимость в сокращениях зависит от используемых библиотек.

## 9.4. Стандартная библиотека Python

Python поставляется с большим набором готовых модулей. Их называют стандартной библиотекой.

Благодаря ей для многих задач не требуется самостоятельно писать весь код с нуля.

Рассмотрим несколько полезных модулей.

|Модуль|Назначение|
|---|---|
|`math`|Математические функции|
|`random`|Случайные значения|
|`datetime`|Даты и время|
|`os`|Взаимодействие с операционной системой|
|`pathlib`|Работа с путями к файлам и каталогам|
|`json`|Чтение и запись JSON|
|`re`|Работа с регулярными выражениями|
|`collections`|Дополнительные структуры данных|
|`statistics`|Статистические вычисления|
|`uuid`|Создание уникальных идентификаторов|

Рассмотрим примеры, которые особенно пригодятся при разработке веб-приложений.

### Модуль `datetime`

Используется для работы с датами и временем.

```python
from datetime import datetime
current_time = datetime.now()
print(current_time)
print(current_time.year)
print(current_time.month)
print(current_time.day)
```

Например, приложение может сохранять дату регистрации пользователя или время создания заказа.

### Модуль `json`

JSON — популярный формат обмена данными между клиентом и сервером.

```python
import json
user = {"id": 1, "name": "Алексей", "age": 20}
json_text = json.dumps(user, ensure_ascii=False)
print(json_text)
```

Результат:

```
{"id": 1, "name": "Алексей", "age": 20}
```

Функция `json.dumps()` преобразует Python-объект в строку JSON.

Обратное преобразование выполняется с помощью `json.loads()`:

```python
import json
json_text = '{"name": "Алексей", "age": 20}'
user = json.loads(json_text)
print(user["name"])
print(user["age"])
```

Результат:

```
Алексей
20
```

Это особенно актуально для веб-разработки, где сервер часто принимает и возвращает данные в формате JSON.

### Модуль `uuid`

UUID — идентификатор, предназначенный для уникального обозначения объектов.

```python
import uuiduser_id = uuid.uuid4()
print(user_id)
```

Пример результата:

```
a2d81f72-8f48-4d21-8f45-9a7e2a5c1d33
```

Значение будет генерироваться заново при каждом вызове.

UUID можно использовать для идентификации файлов, заказов и других объектов. При этом он не заменяет механизмы проверки прав доступа и не должен автоматически считаться секретным токеном.

## 9.5. Создание собственных модулей

Теперь перейдём к более важной для разработки части: созданию собственных модулей.

Представим, что мы разрабатываем небольшую систему управления пользователями.

Создадим следующую структуру:

```
project/
├── main.py
└── users.py
```

В файле `users.py` разместим логику работы с пользователями.

```python
users = [
    {"id": 1, "name": "Алексей"},
    {"id": 2, "name": "Мария"},
    {"id": 3, "name": "Иван"}]
def get_all_users():
    return users
def get_user_by_id(user_id):
    for user in users:
        if user["id"] == user_id:
            return user
        return None
```

Теперь в `main.py` импортируем модуль:

```python
import users
all_users = users.get_all_users()
for user in all_users:
    print(user["name"])
user = users.get_user_by_id(2)
print(user)
```

Результат:

```
Алексей
Мария
Иван
{'id': 2, 'name': 'Мария'}
```

Мы отделили данные и функции, связанные с пользователями, от основной логики программы.

Это первый шаг к построению более крупного приложения.

### Импорт нескольких функций из собственного модуля

Вместо импорта всего модуля можно импортировать конкретные функции:

```python
from users import get_all_users, get_user_by_id
print(get_all_users())
print(get_user_by_id(1))
```

При этом файл `users.py` должен находиться в доступном для импорта расположении, например рядом с `main.py`.

### Важный момент: модуль выполняется при импорте

Рассмотрим файл `example.py`:

```python
print("Модуль был загружен")
def hello():
    print("Привет!")
```

Теперь в `main.py` напишем:

```python
import example
```

При первом импорте выведется:

```
Модуль был загружен
```

Это происходит потому, что Python выполняет инструкции, находящиеся на верхнем уровне импортируемого модуля.

Поэтому не следует размещать на верхнем уровне модуля действия, которые не должны выполняться при каждом запуске программы или которые требуют осторожного управления: например, запуск сервера, удаление файлов или выполнение миграций базы данных.

Обычно модуль содержит определения функций, классов и констант, а запуск приложения организуется отдельно.

## 9.6. Переменная `__name__` и `if __name__ == "__main__"`

Это одна из важнейших конструкций при организации Python-проектов.

Рассмотрим файл `calculator.py`:

```python
def add(a, b):
    return a + b
print("Калькулятор загружен")
print(add(10, 5))
```

Если запустить `calculator.py` непосредственно, получим:

```
Калькулятор загружен
15
```

Но что произойдёт, если импортировать этот файл из другого модуля?

```python
import calculator
```

При импорте тоже выведутся сообщения:

```
Калькулятор загружен
15
```

Это может быть нежелательно. Мы хотели подключить функции, а вместо этого получили выполнение демонстрационного кода.

Чтобы разделить импорт модуля и самостоятельный запуск программы, используется специальная переменная `__name__`.

Python автоматически устанавливает её значение.

- Если файл запущен непосредственно, `__name__` получает значение `"__main__"`.
    
- Если файл импортирован как модуль, `__name__` обычно содержит имя этого модуля.
    

Исправим пример:

```python
def add(a, b):
    return a + b
if __name__ == "__main__":
    print("Калькулятор запущен")
print(add(10, 5))
```

Теперь поведение отличается.

При непосредственном запуске `calculator.py` мы увидим:

```
Калькулятор запущен
15
```

При импорте:

```python
import calculator
print(calculator.add(20, 5))
```

Результат:

```
25
```

Сообщение `Калькулятор запущен` не выводится.

Почему? Потому что условие `if __name__ == "__main__":` выполняется только при самостоятельном запуске файла как основной программы.

Запомните: конструкция `if __name__ == "__main__":` позволяет отделить основной сценарий запуска от кода, предназначенного для повторного использования.

Она особенно полезна для:

- запуска тестовых примеров;
    
- проверки отдельных модулей;
    
- выполнения скриптов;
    
- запуска приложения;
    
- организации точки входа проекта.
    

При этом сам по себе импорт не является способом запуска веб-сервера: запуск приложения Flask или FastAPI зависит от того, как организован проект и какой командой его запускают.

## 9.7. Что такое пакет Python

Когда проект состоит из нескольких модулей, их можно объединять в каталоги по смыслу.

Пакет — это способ организации модулей в иерархическую структуру.

Представим проект интернет-магазина:

```
shop/
├── main.py
├── users/
│   ├── __init__.py
│   ├── models.py
│   └── services.py
└── products/
    ├── __init__.py
    ├── models.py
    └── services.py
```

В этом примере:

- `users` — пакет, связанный с пользователями;
    
- `products` — пакет, связанный с товарами;
    
- `models.py` содержит определения моделей;
    
- `services.py` содержит функции, реализующие операции над данными.
    

Файл `__init__.py` традиционно используется для обозначения пакета и может содержать код его инициализации или необходимые экспорты.

В современных версиях Python существуют и так называемые namespace packages, которым `__init__.py` не обязателен. Тем не менее в учебных проектах и обычных приложениях явные файлы `__init__.py` помогают сделать структуру понятнее.

### Импорт из пакета

Допустим, в файле `users/services.py` находится функция:

```python
def get_user_name(user):
    return user["name"]
```

В `main.py` можно написать:

```python
from users.services import get_user_name
user = {"id": 1, "name": "Алексей"}
print(get_user_name(user))
```

Результат:

```
Алексей
```

Разберём путь импорта:

```python
from users.services import get_user_name
```

- `users` — пакет;
    
- `services` — модуль внутри пакета;
    
- `get_user_name` — функция внутри модуля.
    

Таким образом, Python позволяет организовать даже большой проект в логическую иерархию.

## 9.8. Абсолютные и относительные импорты

В Python встречаются два основных подхода к указанию пути импорта.

### Абсолютный импорт

Абсолютный импорт указывает полный путь от доступного корня импортов.

Например, структура проекта:

```
shop/
├── main.py
└── users/
    ├── __init__.py
    ├── models.py
    └── services.py
```

В `main.py`:

```python
from users.models import Userfrom users.services import get_user_name
```

Путь явно указывает, из какого пакета и модуля мы берём объект.

Для крупных проектов абсолютные импорты часто оказываются наиболее понятными.

### Относительный импорт

Относительный импорт указывает путь относительно текущего пакета.

Предположим, внутри `users` появились следующие файлы:

```
users/
├── __init__.py
├── models.py
└── services.py
```

В файле `services.py` необходимо импортировать класс `User` из `models.py`

Можно использовать абсолютный импорт:

```python
from users.models import User
```

Или относительный:

```python
from .models import User
```

Одна точка означает текущий пакет.

Две точки означают родительский пакет.

Например:

```python
from ..database.connection import get_connection
```

Такой импорт поднимается на уровень выше текущего пакета, а затем обращается к `database.connection`.

Относительные импорты обычно применяются внутри пакетов. Они зависят от того, как Python загружает модуль, поэтому при попытке запустить отдельный файл напрямую иногда возникает ошибка:

```bash
ImportError: attempted relative import with no known parent package
```

Это не обязательно означает, что сам импорт написан неправильно. Возможно, файл запущен не в контексте пакета.

В таких ситуациях важно правильно запускать приложение из корня проекта.

## 9.10. Типичные ошибки при импорте

### Ошибка 1. Python не находит модуль

Например:

```python
import users
```

Но интерпретатор сообщает:

```bash
ModuleNotFoundError: No module named 'users'
```

Возможные причины:

- файл находится не там, где ожидается;
    
- Python запускает программу из другой рабочей директории;
    
- название модуля указано неправильно;
    
- каталог проекта не входит в доступные пути импорта;
    
- не установлена необходимая внешняя библиотека.
    

Первое, что следует проверить, — структура файлов и способ запуска программы.

### Ошибка 2. Конфликт имён

Предположим, мы создали собственный файл:

```python
random.py
```

И внутри написали:

```python
import random
```

Возникает проблема: наш файл может затенить стандартный модуль `random`

В результате Python попробует импортировать наш файл вместо стандартного модуля, что способно привести к циклическому импорту или другим ошибкам.

Поэтому не стоит называть собственные файлы именами популярных стандартных модулей и библиотек, например `random.py`, `json.py`, `datetime.py` или `flask.py`.

### Ошибка 3. Циклический импорт

Представим два файла.

`users.py`:

```python
from orders import get_orders
def get_users():
    return ["Алексей", "Мария"]
```

`orders.py`:

```python
from users import get_users
def get_orders():
    return ["Заказ 1", "Заказ 2"]
```

Теперь модули зависят друг от друга.

Это называется циклическим импортом.

Он не всегда приводит к ошибке, но может вызвать ситуацию, когда один модуль пытается получить объект из другого до того, как тот был полностью инициализирован.

Обычно проблему решают пересмотром структуры проекта: например, выделяют общую логику в третий модуль или устраняют ненужную взаимную зависимость.

### Ошибка 4. Неправильное использование `__name__`

Если код должен выполняться только при самостоятельном запуске файла, но находится вне условия:

```python
if __name__ == "__main__":
```

то он будет выполняться и при импорте модуля.

Это может приводить к неожиданным сообщениям в консоли, повторному запуску логики или другим нежелательным действиям.

### Ошибка 5. Неправильный относительный импорт

Например:

```python
from .models import User
```

Если запустить файл напрямую, Python может не распознать его как часть пакета.

Вместо запуска файла изнутри пакета напрямую обычно лучше запускать приложение из корня проекта подходящим способом.

## Итоги занятия

После изучения темы необходимо понимать следующие понятия:

- Модуль — отдельный файл Python, содержащий код.
    
- Пакет — способ группировки модулей в каталоги и иерархию.
    
- `import` — импорт модуля.
    
- `from ... import` — импорт конкретных объектов из модуля.
    
- `as` — создание псевдонима.
    
- `__name__` — специальная переменная, отражающая контекст запуска или импорта модуля.
    
- `if __name__ == "__main__":` — условие для кода, который должен выполняться при самостоятельном запуске файла.
    
- Абсолютные и относительные импорты позволяют указывать путь к объектам в проекте.
